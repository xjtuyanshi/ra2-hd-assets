# Native host bridge (development only)

The native host runs the player's original 32-bit executable in its own process. A fork of cnc-ddraw supplies the local agent; the existing development page and HD renderer attach to a frame-boundary mirror through the same Worker/shell seam. This is an experimental backend. Offline builds and synthetic tests do not establish the live acceptance gates.

## Build and ownership

On macOS, [the owner launcher](../../packages/native-host/launcher/README.md) provides a single entry point:

```sh
RA2_NATIVE_GAME_DIR="$GAME_COPY" \
RA2_NATIVE_WINE_BOTTLE="$BOTTLE_NAME" \
RA2_NATIVE_WINE="$WINE_EXECUTABLE" \
RA2_HD_CACHE_DIR="$HD_CACHE" \
scripts/remaster/native/play-native.sh --open
```

Use `RA2_NATIVE_WINE_PREFIX="$WINE_PREFIX"` instead of a named CrossOver bottle for plain Wine. The launcher builds missing local binaries, backs up the supplied copy's existing DLL before replacement, uses two free allowed ports and a fresh token, starts the hidden owned game and loopback page, and prints the exact private URL. `--open` opens Google Chrome; the page automatically selects the supplied YR resources and attaches to that game. The HD options are shared with `scripts/remaster/play.sh` through `scripts/remaster/play-options.mjs`. Exit stops only processes it created and conditionally restores its DLL. It obtains no resources. Native Wine process ownership and browser rendering require a real owner run; build and synthetic lifecycle checks are separate evidence.

`--size WxH` sets the match resolution before launch, for example `--size 1280x720`. The default is the primary macOS display's size in points, conservatively bounded to the repository's shared 800×600 through 2560×1600 session range and the native picture protocol's 2,097,152-pixel limit. The launcher changes only the resolution keys in the supplied copy's `RA2MD.INI`, preserves other ANSI bytes/settings, and retains an original backup when changing an existing INI. Symlinks, Unicode BOM files and ambiguous INI case variants are refused before rewriting. The chosen resolution persists in that copy. **Native resolution is fixed for the session:** resizing Chrome scales the picture; stop and relaunch to change the game's size. Native menus retain their original dimensions until battle starts. A launcher process without display access must use `--size` explicitly. The printed URL carries the actual fixed size instead of the v86-only `resolution=display` behavior.

Native sessions use absolute browser mouse coordinates by default, equivalent to `mouse-lock=0`, so menu clicks work even without a preceding move. `mouse-lock=1` explicitly opts into relative Pointer Lock. The emulator keeps its established Pointer Lock default. The page's key/input path still owns its normal cleanup and release behavior.

For a bounded check of the owner's actual Google Chrome launch, run `node scripts/remaster/native/owner-open-acceptance.mjs --out "$OUT"` through the authorized runner. It reads the explicit environment or the private `OUT/run/owner-launch-smoke.json`, supports `--config` / `--size`, and holds the ready page for 60 seconds (`--hold-seconds` accepts 1–90). The private `OUT/browser/owner-open-current.json` contains its exact token-bearing URL and `closeProofPath` for CUA inspection. The root must close that exact launch tab through CUA, then write `{ "closed": true, "url": "EXACT_LAUNCH_URL", "source": "CUA" }` to that private proof path. The wrapper performs no Chrome-tab automation. A matching proof ends the wait early; missing proof leaves tab closure explicitly `UNVERIFIED`. Final cleanup always interrupts its owned launcher and checks the game stopped, ports released and DLL restored. Native lifecycle metadata does not replace the root's visible CUA acceptance.

Run `bash packages/native-host/build.sh` with the installed i686 MinGW tools. No download or package installation is performed. The ignored output is `packages/native-host/build/ddraw.dll`. Copy it into a dedicated copy of the player's game, retaining the previous DLL for rollback. The vendored MIT source and its exact changes are described in [the vendor README](../../packages/native-host/third_party/cnc-ddraw/README.md); our C implementation lives in `packages/native-host/agent/`.

The agent is disabled without explicit configuration, preserving stock drawing, physical input and game pacing. A configured agent defaults to hidden operation, including before a client connects and after it disconnects. The DLL never changes the game speed on its own. A client may request the game's existing speed setting; smoke tools restore it after measurement.

Configure the copied game's `ddraw.ini`:

```ini
[agent]
enabled=1
port=15450
token=REPLACE_WITH_RANDOM_HEX
origin=http://127.0.0.1:15451
hidden=1
```

Use a random 32–128 digit hexadecimal token, for example `node -e 'console.log(require("node:crypto").randomBytes(32).toString("hex"))'`. The same values can be supplied through `RA2_NATIVE_AGENT_PORT`, `RA2_NATIVE_AGENT_TOKEN` and `RA2_NATIVE_AGENT_ORIGIN`. Do not publish the token. The server binds only `127.0.0.1`, permits ports 15450–15459, checks the configured Origin exactly, authenticates `/?token=HEX`, and admits one client. Tokenless clients and other origins are rejected. The handshake and incoming WebSocket packets have size/time limits. Fragmented, text, unmasked or malformed application packets are rejected.

Set `RA2_NATIVE_AGENT_HIDDEN=1` in the launcher for the intended product mode. `RA2_NATIVE_AGENT_HIDDEN=0` opts into visible development windows; if the environment variable is absent, `[agent] hidden=0` also opts out. The environment setting overrides INI. Hidden mode retains requested logical window visibility and geometry for the game and input routing while suppressing physical top-level visibility, activation and focus. Cursor, key and capture APIs remain virtual with no client. Presentation uses a transient windowed GDI configuration without saving those overrides; pictures are taken from the DirectDraw primary before presentation. No game window is needed on the player's desktop.

For hidden Wine sessions, launch the existing GUI launcher directly, without `explorer /desktop`, and run GUI control helpers the same way. The virtual desktop creates a visible explorer window before the DLL can hide game windows. Visible debugging may retain the private `explorer /desktop=ra2dev,...` recipe with `RA2_NATIVE_AGENT_HIDDEN=0`. If an existing hidden launch still uses that private desktop, set `RA2_NATIVE_AGENT_DESKTOP=ra2dev` (or `[agent] desktop=ra2dev`): the optional guard hides only the matching current Wine desktop of class `#32769`. It does not alter a Windows system desktop or another Wine desktop. `hiddenHost` in hello and diagnostics reports the expected/observed desktop and guard outcome.

## Binary protocol, version 1

One WebSocket carries requests, replies and streaming updates. All application messages are binary and all integers little-endian. The 16-byte header is `magic:u32 = 0x3142484e`, `version:u16 = 1`, `type:u16`, `requestId:u32`, `payloadLength:u32`. Correlated replies preserve request ID and type; errors use type 13 with UTF-8 explanation. Stream messages use ID zero. Client requests and ACK notifications use nonzero IDs. ACK is a notification without a response.

| Type           | Payload / response                                                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 Hello        | UTF-8 JSON: protocol, pid, gameThreadId, exe `{size,peTimestamp,sha256,verified}`, surface `{width,height,bpp,format}`, limits                                      |
| 2 Read         | Request address, length, expectedFrame; reply frame, address, length, bytes. `0xffffffff` means an unconstrained direct read.                                       |
| 3 Write        | Address, length, bytes; empty success. Restores region protection after writing.                                                                                    |
| 4 Alloc        | Size, preferredAddress, executable; reply address, size. Preferred nonzero must be satisfied exactly.                                                               |
| 5 Free         | Agent-owned allocation address; empty success.                                                                                                                      |
| 6 Subscribe    | rangeCount, ruleCount, maxPages, budgetUs, sampleCount; ranges `(address,length)`; rules `(kind,source,bytes,maxCount,stride)`. Replaces the prior subscription.    |
| 7 Mirror       | frame, flags, pageCount, sampleCount; each page address then 4096 bytes; each independent direct sample address, length, bytes                                      |
| 8 Credit       | Exactly one; asks for the current or next primary-surface picture.                                                                                                  |
| 9 Picture      | frame, width, height, rowCount; changed rows `(y,encodedLength,segments)`                                                                                           |
| 10 Input       | kind, a, b, c; kind 1 = postMessage, 2 = key state, 3 = cursor position; empty success                                                                              |
| 11 Diagnostics | Empty request; JSON counters including logicFrames, mirrorBytes, hookUs, hookMaxUs, droppedUpdates, truncation, frameHook and gameThreadId                          |
| 12 Hook        | Boolean u32; enable/disable the version-checked frame hook.                                                                                                         |
| 13 Error       | UTF-8 error; never an assumed success                                                                                                                               |
| 14 Input state | Empty request; JSON API-consumption/message-delivery counters, cursor, held keys, modal owner and bounded control metadata                                          |
| 15 ACK         | Frame u32 acknowledging the sole in-flight mirror                                                                                                                   |
| 17 Sample      | count, then address/length pairs (up to 16). These direct samples are captured on the logic thread before random samples.                                           |
| 16 Batch       | count; entries address, length, expected original bytes, replacement bytes. All originals must match before any mutation; bounded suspend/patch/rollback operation. |

Follow rules retain the five-u32 layout `(kind, source, bytes, maxCount, stride)`. The optional `hello.limits.followRuleKinds` lists supported kinds. A pointer rule (1) follows the pointer at `source`; a pointer-vector rule (2) follows each object using items at `source+4` and count at `source+16`. A span-vector rule (3) follows the same vector's `(count−1)×stride+bytes` contiguous span. Kinds 4–8 begin with an outer pointer vector at `source`. Kind 4 follows an embedded pointer vector at each parent plus `stride`; kind 5 follows a pointer field at that offset; kind 6 follows an embedded capacity vector using items at member+4, capacity at member+8 and `bytes` per element. For kinds 7 and 8, `stride` packs a first pointer-field offset in its low 16 bits and a child offset in its high 16 bits: kind 7 follows the child's embedded pointer vector, and kind 8 follows the child's pointer field. All intermediate descriptors/fields, pointer lists and final `bytes` blocks belong to the same frame. `maxCount` bounds both outer and inner counts. Null pointers and empty vectors are valid; nonempty vectors require nonnull items. Counts, addresses, arithmetic, total pages and hook time remain bounded; invalid reads become explicit mirror flags or request errors.

The sparse reader working set keeps learned pages individually with separate reader/installer owners. Only a successful complete cold reader operation replaces that reader's prior footprint; warm cached reads retain its dependencies. Readers refresh their caches once per second, so retired heap pages are not retained indefinitely. A caught miss or incomplete mirror cannot prune the working set and remains an acceptance failure.

For development audits, `NativeCore.getMirrorFootprint()` synchronously returns detached subscription ranges, their unique page counts, each owner's learned and exclusive pages, and the follow rules actually sent by the last successful subscription. It performs no guest read or RPC and is independent of the public `VmDiagnostics` and Worker ABI. Mirror membership and `lastPublishedFrame` always describe the last accepted complete image; after a truncated or invalid update, `complete=false` and `currentFollowDemand="unknown"` explicitly distinguish that retained image from current demand. The owner's full accessed footprint is not the learned seed: only previously missing pages enter the learned subscription union. Audit calls belong outside a measured browser performance window.

YR's map discovery captures the pointer table's validated `VectorClass` capacity as well as active cell pages. The pointer-follow rule seeds only its first entry; a strict read of the full actual table uses the existing missing-page subscription and later complete-mirror retry before publishing the discovered ranges. Table relocation, capacity or bounds changes, and frame resets invalidate discovery. Invalid or unavailable descriptors and short reads fail without replacing the prior scope. This avoids following heap pages beyond the actual table allocation; the 512×512-slot validation ceiling and global 4096-page limit remain unchanged.

House capture follows `[0,0x5800)` and discovers the separate `[0x15FF4,0x16060)` tail of every actual house, including Neutral and Special. The prefix covers state/command ownership, sidebar factories/counters/power, mind-control RGB at `+0x56F9` and the allies mask at `+0x5788`; state-reader names, palette and starting point occupy the tail. The tail starts before `+0x16000` because `PlainName[21]` begins at `+0x15FF4`. No current reader consumes the intervening allocation span. Discovery validates the complete actual pointer vector against the existing house bound, keys its cache by all pointers as well as items/count, and refreshes on frame rewind. Invalid, short or missing tables cannot publish partial tails. Cell and house discoveries compose before Core's existing complete subscription-revision barrier permits a reader to run; no follow-rule kind, page limit or game state is changed.

Limits are 32 MiB per application message, 4096 mirror pages/ranges, 256 follow rules, 64 samples and a 100–20000 μs configured hook budget. Allocation ownership is bounded separately. The I/O owner prepares the explicit ranges' page membership once per subscription revision; it does not cache their bytes or dynamic pointers. The subscription and bounded page seed are installed together. The game thread still resolves every follow rule and captures the full current union at one logic boundary, using nonblocking locks, preallocated buffers and a mailbox swap; only the I/O thread touches the socket. Dirty page generations accumulate until the client ACKs. While a mirror is outstanding, the hook coalesces intermediate captures into droppedUpdates rather than doing work that cannot be published. After ACK, it captures the complete current union against the exact acknowledged shadow. Slow clients receive the newest complete image, including every still-dirty page. A budget overrun is reported, never hidden by clock changes.

The final capture reads contiguous runs of at most 16 pages (64 KiB). A boundary-scoped region cursor reuses the last successful `VirtualQuery` interval so adjacent runs in the same committed readable region do not repeat its metadata query. Every byte of each run must still lie within validated readable regions, and every run performs a fresh `ReadProcessMemory` that must return its entire requested length. Failed queries, malformed intervals, unreadable regions and failed or short kernel reads invalidate the cursor and fail the capture. Metadata never survives a capture boundary; page bytes are not reused from the rule-discovery cache. Independent direct samples retain their separate validation path. The page cap, read batch bound and negotiated time budget are unchanged.

Mirror flag 1 means truncated, flag 2 resets the subscription baseline, flag 4 means invalid pages. Clients discard incomplete frame images and retain their previous good reader result. Independent sample bytes are copied directly on the same game thread and logic frame, then compared with the mirror by the smoke tool. An I/O-thread `Read(expectedFrame)` only reports success when the frame counter is unchanged around the read; it is not a frozen full-frame capture.

The optional `hello.limits.pageRemovals=true` capability supports allocation membership changes without a full mirror reset. A supporting client sets bit 31 of the Subscribe `sampleCount` word; the remaining 31 bits still hold a count of at most 64. Initial mirrors retain flag 2 and the original layout. A complete delta with flag 8 appends `removedCount:u32` and that many strictly increasing, unique, page-aligned addresses **after all samples**. The removal count is bounded by 4096, including when a newer subscription lowers `maxPages`. Removed pages cannot also appear among updated pages. Clients validate the whole message, remove retired pages and install changed pages atomically; a page can be added again by a later update. Flag 8 cannot accompany reset, truncated or invalid flags. Clients that do not opt in retain the original reset behavior and receive no removal tail. The agent commits its next shadow only after successful complete publication, so an abandoned update cannot erase a pending removal.

The optional `hello.limits.subscribeRevision=true` makes subscription barriers exact when page removals are negotiated. Subscribe replies contain the installed `revision:u32`. Each complete Mirror sets flag 16 and appends its applied `revision:u32` as the final word, after any removal tail; initial reset may therefore carry flags 18, a normal delta 16, and a removal delta 24. Incomplete mirrors carry no revision tail. NativeCore enables removal deltas only when both capabilities are advertised, and waits for a complete frame at the requested revision before rebuilding readers. A stale in-flight delta cannot satisfy that barrier. Legacy clients retain empty Subscribe replies and reset-based barriers.

The optional `hello.limits.maxBudgetUs` advertises the agent's supported capture budget, bounded by 20000 μs. NativeCore and reader-smoke request at most 12000 μs from capable agents and retain the 4000 μs budget when the field is absent. A nearly 4096-page full-map bootstrap requires copying and serializing roughly 16 MiB at one boundary; the original 4000 μs cap can truncate that complete initial image before any useful delta exists. Subsequent allocation changes use page-removal deltas to avoid repeating that bootstrap. The negotiated budget remains explicit; overruns continue to fail the update and remain visible in diagnostics.

Picture rows contain u16 segments. Bit 15 selects a run of RGB565 key colour `0xf81f`; bits 0–14 give a nonzero pixel count. Literal runs are followed by that many u16 pixels. A row must decode to exactly the width. The first picture and every size change contain all rows. One credit is outstanding at a time; the agent advances its exact picture baseline only after successful sending. A credit also wakes the native GUI owner to capture the actual current primary, so an already drawn static menu does not wait for another presentation. Nonblocking primary/surface locks and bounded GUI timer retries avoid blocking reentrant surface owners. Surface creation, reconfiguration and final teardown belong to the game GUI owner; foreign-thread DirectDraw lifecycle changes are unsupported.

## Mirror and installer semantics

The adapter owns the socket, sparse pages, request timeouts, frame credits, retry scheduling and destruction. Game policies supply addresses, follow rules, reader factories, speed writes and passthrough installation. YR facts stay under `src/games/yr/`; generic native mechanisms stay under `src/adapter/native/`. No architecture allowlist changes are necessary.

Sparse reads never synthesize zero bytes. `NativeMemoryMiss` subscribes the absent pages. Even if an existing optional reader catches that exception, the operation records the miss, discards the entire result and recreates its reader factories. Reader retries use complete mirror frames; asynchronous direct reads never contaminate the frame image. An installer runs against a private transaction image, buffers every write and restarts the whole operation after fetching absent pages or obtaining allocations. Only a successful complete operation submits an atomic compare-and-write batch. An uncertain commit reply retains executable reservations to avoid dangling jumps.

Attachment at an owned native menu becomes ready for pictures and input without waiting for a nonexistent logic tick. It keeps the mirror incomplete and returns null reader results until the game publishes a complete battle mirror. At that point the backend obtains the actual logic-thread ID and verified hook metadata before creating readers or enabling game patches. `awaitingLogicMirror` in native diagnostics identifies this menu warm-up state. Attachment outside an owned menu still requires the first complete mirror within the existing startup timeout; an invalid match stream is not accepted as menu readiness.

The logic hook validates the pinned executable identity and its full instruction signature before installing a removable detour at the frame counter store. The detour preserves general registers, flags and x87/SSE state. Frame-counter readers validate the actual native detour metadata instead of pretending the patched bytes remain original. Passthrough uses the existing YR installer with an explicit native thread guard, leaving the v86 guard unchanged. Agent-owned stub/data allocations remain alive until process exit; disconnected clients must not leave entry-site patches enabled or erase storage referenced by an in-flight guest call.

Input keeps the existing `postMessage`, key-state and cursor-position operations. Tagged private messages contain queue tickets, never client-provided pointers, and execute on the game window thread. With no dialog, the original battlefield WndProc receives logical game coordinates directly. The topmost enabled, logically visible dialog owned by the game receives menu input. Mouse messages honor the game's validated GUI-owner capture, including its custom `ComboDropWin`, before selecting an owned `ComboLBox` popup or the deepest enabled child at the picture coordinate. Coordinates are converted into the target's client coordinates. Capture does not transfer focus from the popup owner. A release following popup destruction is consumed rather than activating an exposed control. A popup must belong through its owner/parent chain to the current dialog; external window handles are never input targets. Keyboard messages use virtual control focus and dialog navigation. Tab follows native tab order. Focused controls can claim Return/Escape through their actual `WM_GETDLGCODE`, so an open Combo receives its selection/cancel shortcut before dialog defaults. Otherwise Return/Escape invoke an actual enabled default/cancel button where one exists, or reach the original dialog handler. This covers the main menu, skirmish controls, options and nested confirmations through the same page protocol.

No input operation moves the physical cursor or requests OS focus. DirectInput is unsupported. `INPUT_STATE` separates accepted requests, delivered messages and cursor/key API consumption, and adds `dialogMessages`, `lastTargetHwnd`, `lastTargetId`, `dialogHwnd`, and `controls`. Each control reports its numeric handle/ID, parent handle, style, class, cached text, requested visibility, enabled state and `[left,top,right,bottom]` rectangle in native-picture coordinates. Enumeration is limited to 128 entries and 64 KiB JSON; `controlsTruncated` identifies an incomplete list. These diagnostics do not provide a command to invoke arbitrary window handles or send pointer messages. Native menu/battle routing, focus isolation and browser overlays require separate live acceptance.

Input state also reports raw `focusHwnd` and `gameCaptureHwnd`. Accepted dialog presses retain their original target/root until release, including a root disabled by that press or a transition to another page. A validated game popup may take over the original press; an invalid or destroyed target consumes the release before the main-window fallback, instead of releasing onto a newly exposed control. This never enables a disabled dialog or invokes an arbitrary handle. Capture is cleared before the original release callback so a nested new press survives, and disconnect retires pending press ownership. Optional cumulative `redirectedCapturedReleases` and `consumedCapturedReleases` counters expose these lifecycle paths for live verification. Painting has a separate target selection: a logically visible owned disabled dialog still receives genuine painting and its native animation, while new input remains restricted to enabled dialogs. The same painting selection guards every callback and final primary commit; a hide, destruction or page switch ends the old paint pass. `DIAGNOSTICS.hiddenHost` reports optional `lastPaintRootHwnd`, `lastPaintRootEnabled` (at the start of the last actual pass, or `null` before any pass), and cumulative `disabledDialogPaints`. These fields never change window enabledness or provide an input command. Combo controls add `combo: {count,selection,dropped}`; system popup lists add `list: {count,selection,topIndex,itemHeight}`. The game skin uses a genuine captured `ComboDropWin` while the system dropped flag remains false; that flag is never synthesized. Custom item geometry must be inspected in the native picture. Queries use bounded native window messages with 10 ms per query and at most 32 queried enabled Combo/list controls. Unknown results are `null`; an observed selection of `-1` means the real control has no selection. These read-only diagnostics can prove a normal input operation changed a control and restored its original value. Child `ShowWindow` calls preserve the actual API return value: the game uses a child's own previous visibility while temporarily hiding and initializing native menu controls. Ancestor visibility cannot substitute for that result.

## Smoke tools and recordings

`NATIVE_OUT="$OUT" node scripts/remaster/native/browser-acceptance.mjs --size 1280x720 --hold 80` starts the owner launcher and a real headed Chromium page, enters a six-player skirmish through trusted browser mouse and keyboard events, and checks selection, movement, drag selection, production, completed-building placement, scrolling, options/Resume, picture switching, and score/menu return (Abort Mission normally returns directly to skirmish setup). Supply the launcher's environment or `--config` pointing to a private JSON file containing those environment values. The browser uses the installed Chromium cache and the existing Metal/WebGPU launch arguments; it downloads nothing. `--hold 80` uses an ordinary 80 ms press; the no-move case still sends no preceding mouse move, and the quick case moves then presses without an intervening wait. Read-only Worker instrumentation exposes native controls and command state, while development `__hdBridge.diagnostics` records actual distinct deliveries and completed visible draws during a 60-second fight window. `--mode reproduce --mouse-lock 1` retains the previous-position failure case; the native page defaults to absolute mouse coordinates. Screenshots (at most 1280 CSS pixels wide), raw measurements, failed attempts, and cleanup records remain under `$OUT/browser`. Browser and owned game are closed on completion, failure, signals, and the bounded run deadline.

The acceptance run observes six real player slots. `--teams original` is the default and uses their saved original team choices; `--teams free-for-all` selects None for all six, and `--teams three-versus-three` selects team A for the first three slots and team B for the last three. Every change uses the original menu's popups and checks the actual native selection. The run retains the original selections and skirmish `ShortGame` preference in a private baseline across retries; the initial checkbox setting comes from the supplied copy's INI. `--short-game original` is the default; `--short-game true` or `--short-game false` selects that ordinary match option through real checkbox input. The script observes the original picture before/after any change and checks the applied native boolean after Start. In `finally`, including failed runs, it attempts to restore all six original selections and the original `ShortGame` preference through the original menus, then checks the saved INI preference and actual main-menu control. An unavailable or unsuccessful restoration is reported as `UNVERIFIED`. The owned loopback Playwright browser server provides a process handle for bounded, targeted browser shutdown; launcher cleanup also checks game exit, released ports and restored DLL bytes/mode.

`--ai original` is the default and retains the five AI slots' saved original difficulty choices. `--ai easy`, `--ai medium` and `--ai hard` request that standard difficulty for all five through trusted browser clicks. `browser-ai-settings.mjs` validates each active native Combo and its four choices, verifies the popup's capture and parent ownership before clicking, and records the popup screenshot and actual resulting selections. A four-item Combo can have only three visible rows and a scrollbar: the helper selects only fully visible rows and reports `UNVERIFIED` for an offscreen Hard row or a change from an initially Hard selection whose scroll position is unknown. Retaining an unchanged original Hard choice sends no input. It never selects the closed slot or changes the human player. The private AI baseline is saved before the first change and survives failed retries. AI choices are applied before team choices because the original menu can reset an AI's team. The setup-menu `finally` path likewise restores AI choices first, then teams and Short Game, and checks the actual selections before Back. These acceptance options do not change the owner launcher's defaults or the game resources.

Combat scouting is opt-in through `--scout` and is disabled by default. The default path uses the original H, P and S hotkeys with 120 ms presses to centre the camera on the base, select the local combatants and issue Stop. It requires an actual nonempty local combatant selection before recording that path as successful. These ordinary inputs do not guarantee the player's survival or a full minute of fighting; the saved window must independently meet the combat and cadence gates below. The optional scout uses real browser commands and player-visible ground, and does not change fog or direct units to hidden enemies.

The combat camera follows already visible weapon effects with real arrow keys. Outside the saved 60-second performance window, it also observes the game's own newest radar alert at most once per second and presses Space for 120 ms once per changed non-null alert, with the pointer at the tactical centre. It logs the actual before/after view and alert, permits at most 24 jumps in any 240 seconds, and bounds each search to 240 seconds. It does not select hidden enemy coordinates or alter fog visibility.

The saved window requires fresh local-visible weapon evidence in each of its six ten-second buckets. `browser-combat-observer.mjs` owns a page-local animation callback, limits observation to 20 Hz and observes each sampled, newly delivered logic frame at most once, reading the existing development combat snapshot without another VM request. It clones that snapshot only for a new sampled frame, retains at most 20,000 compact observations, and cancels its callback when capture ends. The bridge's independent counters still record every actual distinct delivery and completed draw over the full 60 seconds; the combat observation count never supplies states or frames per second. The observer records the actual clone/filter cost with `performance.now()` in `costsMs`. Sample timestamps and bucket boundaries use the same page performance clock as the capture; repeated frames, truncated observations and render-state ages above 150 ms cannot satisfy the gate. When an already player-visible weapon effect leaves the tactical rectangle, the camera may follow it with a real 60–250 ms arrow press, at most once per second, using the retained page state without another VM state request. Hidden coordinates never supply a target. The window also requires complete known native logic endpoints and no increase in mirror truncation, invalid ranges, budget overflow or misses.

Weapon evidence also includes the original `GUNFIRE`, `APMUZZLE` and `VTMUZZLE` animations only when their native frame count is positive, they are neither building animations nor invisible, and the normal player-visibility and tactical bounds tests pass. Before each window, the observer primes all existing qualifying animation `id`/`uid` pairs, including offscreen and fogged identities. A new pair can contribute only once; a lingering animation or camera return cannot become another shot. Any `animsTruncated` observation fails the sustained-fight gate.

The Short Game checkbox is native control 1358. The toolbar is collapsed before menu input so it cannot cover the square; the script presses the square at its native left edge without a preceding move for 80 ms. Its setter reads only a 5×5 RGB565 sample around the square's centre from the native picture decoder's existing baseline, retaining mean RGB, picture-frame tag, control/sample bounds and a browser screenshot. Orange is checked; neutral grey is unchecked. Unsupported colours or missing pictures stay `UNKNOWN` and cannot authorize another click. Restoration uses this same observed conditional setter. In pinned YR 1.001, Skirmish Start 1559 reads checkbox 1358 at `0x6AD78D`–`0x6AD7BC` and latches `Session.Options.ShortGame` at `0xA8B262`. That read-only session byte can remain stale while the checkbox changes; it is recorded separately and establishes the setting only after Start. INI persistence is checked after the real menu return rather than assuming the engine writes it immediately after a checkbox click.

The raw 60-second capture is saved immediately when capture finishes, before nullable battle or performance diagnostics are read. Logic rate uses the two native performance endpoints' own timestamps; missing endpoints remain unknown. A battle that ends during capture records `battleEnded` and cannot pass the complete fight-window acceptance, but its raw data and genuine ending remain available.

`--fight-windows 1..3` bounds repeated windows in the same native match and defaults to three. Each window has its own raw capture and JSON archive, before/after counters, logic endpoints, mirror quality, command observations and fight samples; earlier failures stay recorded. A successful complete window is selected for the result. Rates, intervals and ten-second weapon buckets are never combined across windows. Later searches are bounded to 90 seconds and skip the first window's picture-switch/display warm-up. The run preserves the match identity and settings, then performs the genuine ending once after measurement.

For repeated normal-mode measurements, append `--skip-comparison`; it is disabled by default. Each window separately records `cadenceMet`, `mirrorQualityMet`, `visibleFightMet` and their complete-window `met` result. This option skips only the subsequent paired-picture work, records the pair as explicitly skipped with `pair.met=false`, and still exercises the genuine ending, menu return, preference restoration and cleanup. Such a run produces no new paired visual evidence. ## Browser start order

The owner launcher above performs the startup sequence and owns cleanup. The following manual sequence remains available for development.

1. Build and install the DLL into the dedicated game copy. Set the agent token and exact HTTP development origin in the copy's `ddraw.ini` or launcher environment. Set `RA2_NATIVE_AGENT_HIDDEN=1` explicitly for product-mode acceptance.
2. Start the original game through the existing GUI launcher in the dedicated Wine bottle, without creating an explorer virtual desktop. For example, `wine --bottle ra2dev 'C:\tools\ra2launch.exe' 'C:\YURI\gamemd.exe'`. Run GUI control helpers without explorer too. The game starts at its hidden main menu. One game at a time. Keep browser and smoke clients sequential because the agent admits one client.
3. Start the existing development server on port 15451, with `RA2_GAME_ROOT` set to a directory containing `ra2/` linked to the dedicated game copy, and `RA2_HD_CACHE_DIR` set to the owner's existing HD cache. The server reads those assets; do not modify the cache. `RA2_DEV_HTTP=1 pnpm exec vite --host 127.0.0.1 --port 15451 --strictPort` avoids an HTTPS page connecting to an insecure WebSocket.
4. Open `http://127.0.0.1:15451/?backend=native&agent=ws%3A%2F%2F127.0.0.1%3A15450&agent-token=TOKEN&hd=1`, replacing `TOKEN` with the same configured hexadecimal token. In this manual URL select Yuri's Revenge and the game resources as required by the existing page; the owner launcher already supplies its explicit auto-start query and complete HD options. The native path attaches to the running process; it does not launch another emulator or native game. The page receives native menu pictures, so use that picture to enter Single Player, Skirmish and Start Game. Alternatively, finish `menu-smoke --step all`, disconnect it and then attach the page to its existing match.
5. On completion stop the page and the dedicated game/bottle using the existing launcher shutdown recipe.
